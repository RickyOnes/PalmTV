# PalmTV release 混淆规则（2026-09-17 重写）
#
# ★ 本文件在 release 构建生效：
#     entry/build-profile.json5 → buildOptionSet[release]
#       → arkOptions.obfuscation.ruleOptions.enable = true
#       → files: ["./obfuscation-rules.txt"]
#   debug 构建**不**做混淆（所以调试包一直正常、问题只在 release 才暴露）。
#
# ★★ 为什么必须有下面的 keep 名单（血泪）★★
#   本工程大量依赖「**名字契约**」：ArkTS 侧用点号访问的属性名，
#   native 侧（libpalmtv_napi.so）是用**字符串**注册的同一个名字。
#   属性混淆会把这些属性名改短（如 jstvSignQuery → y58），而 native 只认原名
#   ⇒ release 包在真机上会变成 `undefined is not a function` / 读到的字段全是 undefined。
#
#   2026-11-07 之前踩过的实例（旧规则下 release 产物的 nameCache）：
#     "cmgInit": "y58"   "cmgDecryptTsAsync": "j59"   "yspSignInit": "x65"   "lastMaPcs": "j63"
#   ⇒ 当时把那些名字全部显式保留了；**CMG 与 Web/PC 签名已于 2026-11-07 移除**，
#     现在只剩「自研 cKey + 江苏台签名」两组接口要保。
# ============================================================================

# ---- 日志：**不用 -remove-log**（2026-09-17 定稿）----
# `-remove-log` 是"全删"：连 `console.error/warn` 一起删（且要求返回值未被使用），
# 而我们要的是"发布包只留 warn/error" ⇒ 已改为在 App 侧用 `common/Log.ets` 按级别封装：
#   Log.i(...)  release 下被 `BuildProfile.DEBUG=false` 静态折叠掉（连参数字符串一起摇掉）
#   Log.w(...) / Log.e(...)  release 下照常输出（hilog tag `JSAPP`）
# ⚠️ 因此：**不要再直接调用 console.***（新代码一律走 Log；否则 release 下会漏出 info 级日志）。
# （2026-11-07 起 native 侧已无 hilog 输出：CMG 解密核连同它的 `cmg_log()` 一并移出鸿蒙构建）
# -remove-log

# 【已作废】官方 cKey 模块体 ckey_core.ts（webpack fb15）—— 2026-09-29 原生化后删除
# ============================================================================
# ckey_core.ts 是**官方混淆模块体**原样编译进来的（见 NativeSigner.ets 注释）：
# 内部可能用 Object.defineProperty / Proxy 的**字符串 key** 定义属性、
# 又用点号访问 ⇒ 属性混淆一旦只改一侧就会静默失效（cKey 为空 ⇒ 取流 20301）。
# 它只占一个文件，整文件不混淆的代价极小，收益是确定性。
#
# ⚠️⚠️ 2026-09-17 实测：写成 `-keep ./entry/src/main/ets/common/ckey_core.ts`（工程根相对）**没生效**，
#   而规则是**静默忽略**的（不报错）—— release 包里 ckey_core.ts 段的 IdentifierCache 仍被改名
#   （`#CKEY_UA → i2`、`ckeyCompute#cnlid → j2`…），真机上表现为：
#     点击频道 → `[YspSign] cKey 计算失败: Cannot load property of null or undefined`
#     → `[Index] 取流失败(1/3…)` → 三次后 `playChannel 失败`，**完全无法播放**（但 debug 包正常）。
#   ⇒ 该模块内部是"字符串 key 定义 + 点号访问"混用的自制实现，属性一被改名就静默取到 undefined。
#
# ★★ 路径基准（2026-09-17 逐条实测，本 SDK 版本上**两种规则的基准不一致**，极易踩）★★
#   `-keep     ./src/main/ets/common/ckey_core.ts`  ← 基准 = **模块目录（entry/）** ✅ 已验证生效
#   `-keep-dts ./entry/src/main/cpp/types/libcmg_napi` ← 基准 = **工程根**（少写 entry/ 会 ENOENT）
#   ⇒ 写错基准**不会报错、只是静默不生效**，所以**改完必须核对** nameCache：
#     `entry/src/main/ets/common/ckey_core.ts` 段的 `IdentifierCache`/`PropertyCache` 必须是 **空 `{}`**；
#     顺带确认自有代码仍被改名（如 `"decTail": "t2"`）⇒ 证明混淆确实在跑、不是"整体没混淆"的假象。
# ★★ 2026-09-29：`ckey_core.ts` **已删除**（cKey 改由 native 的 `ysp_gen_ckey` 计算，
#    见 `NativeSigner.ets`）⇒ 本段 keep 规则一并作废，**不要再补回来**。
#    下面这段历史保留：它记录了"为什么当年必须整文件不混淆"，也是"用 native 换掉 JS"的价值所在。
# -keep ./src/main/ets/common/ckey_core.ts
